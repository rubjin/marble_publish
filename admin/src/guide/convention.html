파일 구조 및 문서 규칙

본 문서는 챌린지 어드민(Admin) 퍼블리싱 작업에 대한 파일 구조, 네이밍 컨벤션, 코딩 규칙을 정의합니다.
개발팀이 React(JSX) 환경으로 원활하게 이관할 수 있도록 가이드하기 위해 작성되었습니다.

1. 파일 구조 (Directory Structure)

admin/
├── build.js                  # 빌드 스크립트 (dist 산출물 생성)
├── package.json              # 프로젝트 설정 및 빌드/컴파일 명령어
├── vite.config.js            # Vite 개발 서버 설정 및 HTML include 플러그인
└── src/
    ├── assets/               # 정적 자원 및 스타일 소스
    │   ├── css/              # 컴파일된 CSS (main.css) 및 외부 라이브러리 CSS
    │   ├── fonts/            # 웹 폰트 (KBFG.woff2 등)
    │   ├── images/           # 이미지 및 아이콘 (SVG 등)
    │   ├── js/               # 공통/유틸 스크립트 (prism.min.js 등)
    │   └── scss/             # SCSS 소스 폴더 (실제 스타일 작업 영역)
    │       ├── base/         # Reset, Variables, Mixins, 공통 기본 스타일
    │       ├── components/   # 버튼, 뱃지, 카드 등 UI 컴포넌트 스타일
    │       └── main.scss     # 진입점 SCSS
    │
    ├── components/           # 재사용 가능한 UI 컴포넌트 HTML 조각
    ├── guide/                # 가이드 문서 (convention.html, guide.html)
    ├── layout/               # 공통 레이아웃 템플릿 (aside, header, footer, layout)
    └── pages/                # 업무별 화면 HTML

2. 네이밍 컨벤션 (CSS Naming Convention)

  • 본 프로젝트는 React(JSX) 환경과의 일관성 및 가독성을 높이기 위해 클래스명에 카멜 케이스 (camelCase) 표기법을 기본으로 사용합니다.
  • 컴포넌트 (Component): 독립적인 의미를 가지는 컴포넌트 단위는 소문자로 시작하는 단어로 작성합니다. (예: .btn, .card)
  • 하위 요소 및 변형 (Element / Modifier): 컴포넌트 내의 하위 요소나 상태 변형을 나타낼 때는 하이픈이나 언더스코어 없이 대문자로 이어붙입니다. (예: .title, .primary)
  • 동적 상태 (State): JS나 React 상태로 제어되는 동적 클래스는 상태 변화를 명확히 알 수 있도록 is 또는 has 접두사를 활용하여 카멜 케이스로 표기합니다. (예: .isActive, .isDisabled)

3. HTML / 문서 작성 규칙

  1. 들여쓰기: Space 2칸을 표준으로 사용합니다.
  2. 빈 태그 닫기: <img />, <input />, <br /> 등은 React 환경을 고려해 반드시 슬래시로 닫습니다.
  3. 인라인 스타일 금지: style="..." 속성은 원칙적으로 배제하고 모든 디자인은 CSS로 제어합니다.
  4. 의미론적 마크업: <div> 남용을 줄이고 <header>, <nav>, <article> 등을 적극 활용합니다.
  5. 접근성(A11y): 버튼 태그에는 항상 type="button"을 명시하고, 스크린 리더용 텍스트는 .a11yHidden 클래스를 사용해 숨김 처리합니다.

4. 컬러 및 테마 (Color System)

  • 국민은행의 아이덴티티를 반영한 컬러 시스템을 사용합니다.
  • Primary: #FFDC00 (KB Yellow)
  • Primary Hover: #E5C600 (Darker Gold)
  • Text/Point: #1f2937 (가독성을 위한 어두운 회색)

5. React 개발팀 인수인계 시 주의사항

  • 퍼블리싱 결과물의 class 속성은 React 적용 시 모두 className으로 일괄 변경하여 적용해야 합니다.
  • 탭, 아코디언 등의 인터랙션은 순수 HTML+CSS 상태 확인을 위해 .isActive를 수동 마크업해 두었습니다. 개발 적용 시 State 값에 따라 토글되도록 연동이 필요합니다.
