파일 구조 및 문서 규칙

본 문서는 챌린지 어드민(Admin) 퍼블리싱 작업에 대한 파일 구조, 네이밍 컨벤션, 코딩 규칙을 정의합니다.
개발팀이 React(JSX) 환경으로 원활하게 이관할 수 있도록 가이드하기 위해 작성되었습니다.

1. 파일 구조 (Directory Structure)

admin/
├── build.js                  # 빌드 스크립트 (dist 산출물 생성)
├── build-watch.js            # dist 실시간 빌드 (npm run dev 실행 시 함께 동작)
├── html-include.js           # <include> 처리 (속성 전달 / slot / 조건부 출력)
├── package.json              # 프로젝트 설정 및 빌드/컴파일 명령어
├── vite.config.js            # Vite 개발 서버 설정 및 HTML include 플러그인
└── src/
    ├── assets/               # 정적 자원
    │   ├── fonts/            # 웹 폰트 (KBFG.woff2 등)
    │   ├── images/           # 이미지 및 아이콘 (SVG 등)
    │   └── js/               # 공통/유틸 스크립트 (ui.js, chartTheme.js 등)
    ├── styles/
    │   ├── css/              # 컴파일된 CSS (globals.css) - 직접 수정 금지
    │   └── scss/             # SCSS 소스 (실제 스타일 작업 영역)
    │       ├── abstracts/    # Variables, Mixins, Functions, Reset, 공통 기본 스타일
    │       ├── components/   # 버튼, 테이블, 폼 등 UI 컴포넌트 스타일
    │       ├── pages/        # 단독 화면 스타일 (로그인, 오류)
    │       └── globals.scss  # 진입점 SCSS
    │
    ├── components/           # 가이드용 UI 컴포넌트 예시 HTML (한 파일에 여러 케이스)
    ├── partials/             # 화면에서 불러다 쓰는 부품 HTML (한 파일에 하나, 텍스트는 속성으로 전달)
    ├── guide/                # 가이드 문서 (convention.html, guide.html, library.html)
    ├── layout/               # 공통 레이아웃 템플릿 (aside, header, footer, layout)
    └── pages/                # 업무별 화면 HTML

2. 네이밍 컨벤션 (CSS Naming Convention)

  • 본 프로젝트는 React(JSX) 환경과의 일관성 및 가독성을 높이기 위해 클래스명에 카멜 케이스 (camelCase) 표기법을 기본으로 사용합니다.
  • 컴포넌트 (Component): 독립적인 의미를 가지는 컴포넌트 단위는 소문자로 시작하는 단어로 작성합니다. (예: .btn, .card)
  • 하위 요소 및 변형 (Element / Modifier): 컴포넌트 내의 하위 요소나 상태 변형을 나타낼 때는 하이픈이나 언더스코어 없이 대문자로 이어붙입니다. (예: .title, .primary)
  • 동적 상태 (State): JS나 React 상태로 제어되는 동적 클래스는 상태 변화를 명확히 알 수 있도록 is 또는 has 접두사를 활용하여 카멜 케이스로 표기합니다. (예: .isActive, .isDisabled)

3. HTML / 문서 작성 규칙

  1. 들여쓰기: Space 2칸을 표준으로 사용합니다.
  2. 빈 태그 닫기: <img />, <input />, <br /> 등은 React 환경을 고려해 반드시 슬래시로 닫습니다.
  3. 인라인 스타일 금지: style="..." 속성은 원칙적으로 배제하고 모든 디자인은 CSS로 제어합니다.
  4. 버튼 타입 명시: 버튼 태그에는 항상 type="button" 또는 type="submit"을 명시합니다.

4. 컬러 및 테마 (Color System)

  • 국민은행의 아이덴티티를 반영한 컬러 시스템을 사용합니다.
  • Primary: #FFDC00 (KB Yellow)
  • Primary Hover: #E5C600 (Darker Gold)
  • Text/Point: #1f2937 (가독성을 위한 어두운 회색)

5. 개발 연동 상태 클래스 (State Classes)

퍼블리싱 산출물은 스크립트 종속성 없이 클래스 추가/제거만으로 모든 상태(활성, 에러, 열림 등)를 제어할 수 있도록 설계되었습니다. 마크업 상의 <!-- [D] ... --> 주석을 참고하여 상태를 바인딩하세요.

  • .isActive : 탭, 세그먼트, 네비게이션 메뉴 등의 활성화(선택) 상태
  • .isOpen : 아코디언, 모달 팝업, 툴팁 강제 노출, 셀렉트 박스 등의 열림/펼침 상태
  • .isError : 인풋, 셀렉트, 텍스트에어리어의 유효성 검증 실패(에러) 상태
  • .isDragOver : 파일 드롭존 영역에 파일이 드래그 오버된 상태
  • .hasUnit / .hasBtn : 인풋 우측 단위, 좌측 접두사, 버튼 결합 레이아웃 제어
  • .flexBetween : 좌우 양 끝 정렬 컨테이너 (결합 클래스: .alignTop, .alignCenter, .alignBottom, .alignRight)
  • disabled / .isDisabled : 버튼, 폼 요소의 비활성화 상태

6. 컴포넌트 아키텍처 & 페이지 패턴

본 시스템은 Atomic 단위 컴포넌트 분리와 컴포저블(Composable) 페이지 조립을 지원합니다.

  • 컴포넌트 1:1 SCSS 매핑: _button.scss, _popup.scss, _searchbox.scss, _table.scss, _card.scss 등 각 컴포넌트별로 독립된 스타일 파일을 제공합니다.
  • 실전 페이지 패턴 (Page Patterns):
    • Pattern 1 (검색 & 그리드): PageHeader + SearchFilterBox + TableTop + Table + Pagination
    • Pattern 2 (등록/수정 폼): PageHeader + FormGroup (2열/단위/태그) + PageBottomAction
    • Pattern 3 (KPI 대시보드): PageHeader + KpiCardGrid (4단) + StatusCardGrid (5단) + SummaryStatBox
    • Pattern 4 (모달 다이얼로그): Modal (Confirm 안내형 / Large 상세 폼 결합형)

7. 부품 불러오기 (include + 속성 전달)

화면 코딩 시 마크업을 복사하지 않고 src/partials 의 부품을 불러온 뒤 텍스트만 속성으로 전달합니다. 부품을 고치면 사용하는 모든 화면에 반영됩니다.

  • 경로: include 를 쓰는 파일 기준 상대 경로 (VS Code 에서 Ctrl+클릭으로 부품 파일 이동)
  • 속성 전달: <include src="../../partials/pageHeader.html" title="미션 목록"></include> → 부품의 {{ title }} 위치에 출력
  • 기본값: {{ resetText | 초기화 }} - 속성이 없으면 기본값 사용
  • 값 없는 속성: full, pageSize 처럼 속성만 쓰면 켜짐
  • 내용 끼워 넣기 (slot): 여는 태그와 닫는 태그 사이의 마크업이 부품의 {{ slot }} 위치에 출력 (include 중첩 가능)
  • 조건부 출력: {{#if count}} ... {{/if}}, {{#if !count}} ... {{/if}}
  • 사용법: 각 부품 파일 맨 위 <!-- [부품] ... --> 주석 참고 (결과물에는 포함되지 않음)
  • 제공 부품: pageHeader, searchBox, searchRow, searchItem, dateRange, tblTop (적용 예: pages/MM/OFR_AM_MM_016.html)
<include src="../../partials/searchBox.html">
  <include src="../../partials/searchRow.html">
    <include src="../../partials/searchItem.html" label="조회일자" full>
      <include src="../../partials/dateRange.html" start="2026.07.01" end="2026.08.31" name="p1Date"></include>
    </include>
  </include>
</include>
